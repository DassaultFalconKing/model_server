# OVMS 2026.5 GEMMAMONSTER local build and test

This is the machine-side procedure for `integration/ovms-2026.5-forward-port`. The target Windows/Intel Arc machine is the authority for compilation and runtime acceptance.

## 1. Checkout and verify source

```powershell
git fetch origin
git switch integration/ovms-2026.5-forward-port
git pull --ff-only origin integration/ovms-2026.5-forward-port
git rev-parse HEAD
git status --short
pwsh -File .\scripts\gemma4\audit-forward-port.ps1 -OutputPath .\tmp\gemma4-audit.json
```

The audit must finish with `FAIL=0`. The current Responses `parallel_tool_calls` serialization item is expected to appear as a warning until the delegated local one-line patch is applied.

## 2. Apply the delegated Responses one-line patch

Use the exact checked-out `src/llm/apis/openai_responses.cpp`. Find the serialization of the `parallel_tool_calls` response field that currently emits constant `true`. Replace only that value with the parsed request policy (`request.parallelToolCalls`, or the exact current equivalent if upstream changed the enclosing access). Do not replace the file from the 2026.4 branch.

```powershell
git diff -- src/llm/apis/openai_responses.cpp
```

Keep this diff deliberately narrow and record the local commit SHA or dirty diff in evidence.

## 3. Build pinned 2026.5 dependencies and OVMS

```powershell
pwsh -File .\scripts\gemma4\build-local-candidate.ps1 `
  -ShortRoot g5 `
  -Label 2026.5-candidate
```

Use `-ExpungeDependencies` for a clean dependency extraction or `-SkipDependencies` to reuse already installed pinned dependencies. Python/Jinja support is enabled by default.

The wrapper records the exact source HEAD, dependency contract, `ovms.exe` SHA256 and runtime provenance under `tmp/gemmamonster-acceptance/2026.5-candidate/`.

## 4. Prepare one immutable Google-template model overlay

Use the same overlay for 2026.4 control and 2026.5 candidate.

```powershell
pwsh -File .\scripts\gemma4\prepare-google-template-overlay.ps1 `
  -SourceModelPath 'C:\llm\models\OpenVINO\Wondernutts\gemma-4-26B-A4B-it-qat-q4_0-unquantized-uncensored-heretic-int4-ov' `
  -OverlayPath 'C:\llm\models\OpenVINO\gemma4-google-template-overlay'
```

Do not recreate this overlay between A/B runs.

## 5. Launch the current working Profile E

Profile E is the primary runtime profile. Its committed contract lives in `runtime/gemmamonster-ovms-E/profile.json`.

```powershell
pwsh -File .\scripts\gemma4\launch-gemma4-candidate.ps1 `
  -OvmsExe '.\bazel-bin\src\ovms.exe' `
  -ModelPath 'C:\llm\models\OpenVINO\gemma4-google-template-overlay' `
  -ModelName 'gemma4-26-heretic' `
  -ShortRoot g5 `
  -Label '2026.5-candidate' `
  -Profile E `
  -ChatTemplateMode JINJA `
  -RestPort 8000 `
  -GrpcPort 9000
```

Profile E pins GPU + VLM_CB, `max_num_seqs=1`, `DYNAMIC_QUANTIZATION_GROUP_SIZE=0`, `KV_CACHE_PRECISION=u8`, prefix caching enabled and `max_tokens_limit=65536`. Its exact `cache_size` was not preserved in the frozen repository, so the launcher intentionally omits `cache_size` for E rather than borrowing B2/C values.

`Stable` is the B2-style diagnostic profile with prefix caching disabled and cache size 0. `PrefixCache` is the C-style diagnostic profile with prefix caching enabled and cache size 8. Neither is an alias for E.

## 6. Run chained and reliability acceptance

In another PowerShell session:

```powershell
pwsh -File .\scripts\gemma4\run-candidate-acceptance.ps1 `
  -OvmsExe '.\bazel-bin\src\ovms.exe' `
  -ModelName 'gemma4-26-heretic' `
  -BaseUrl 'http://127.0.0.1:8000' `
  -Label '2026.5-candidate' `
  -Reliability Smoke `
  -TemplateProvenancePath 'C:\llm\models\OpenVINO\gemma4-google-template-overlay\gemma4-template-provenance.json'
```

The runner executes two-turn chains in `named`, `required` and `auto` modes, then a grounded reliability smoke matrix. After smoke is clean, rerun with `-Reliability Full` before promotion.

## 7. A/B against frozen 2026.4

Run the frozen 2026.4 binary with the **same Profile E**, same model/template overlay, same ports one server at a time, same tool catalog and same sampling values. The launcher is binary-version agnostic and generates the runtime config locally.

Do not compare Profile E on one binary against B2/C on the other and call it an OVMS result. Configuration confounders have already had enough attention.

## Acceptance interpretation

A 2026.5 candidate is ready for deeper dogfood only when target-machine build succeeds, server readiness passes, named/required/auto chains pass, grounded values survive round-trip, session resume works, and the reliability campaign does not regress against frozen 2026.4. Keep the 2026.4 freeze untouched until that evidence exists.

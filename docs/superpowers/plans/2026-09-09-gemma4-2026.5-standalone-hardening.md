# Gemma4 OVMS 2026.5 Standalone Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the OVMS 2026.5 Gemma4 server sustain tool-call continuations on its own, preserve the new reasoning parser, ship a standard Windows release package, and evaluate performance only after correctness and packaging are proven.

**Architecture:** Reproduce the OpenCode request boundary at the HTTP API, trace the request through chat-template rendering, generation policy, reasoning parsing, and tool parsing, then add the smallest server-side correction guarded by a regression contract. Package the verified binary through the standard OVMS Windows release flow and add profile-E runtime assets outside `bazel-bin`.

**Tech Stack:** C++17, Bazel, OpenVINO GenAI, MediaPipe, PowerShell, OpenAI-compatible `/v3/chat/completions` API.

**Spec:** `docs/gemma4/opencode-first-toolcall-stop-2026-09-09.md` plus the approved ordering in this plan.

## Global Constraints

- Work only on `integration/ovms-2026.5-forward-port`; do not rebuild OVMS 2026.4.
- The server must work without relying on OpenCode title-agent suppression or forced client sampling parameters.
- Preserve the new Gemma4 reasoning parser and its streamed reasoning-boundary behavior.
- Correctness and release-package verification precede performance work.
- Never treat `bazel-bin` as a durable release location.
